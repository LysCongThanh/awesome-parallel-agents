# Contribution Guidelines

Thanks for helping. A first pull request here should take about five minutes: add one line, open the PR, done. Your own project is welcome if it meets the criteria below.

## What belongs here

An entry must help people run more than one AI coding agent on the same codebase safely. That covers worktrees, environment isolation, orchestration, terminal integration, merging, review, guardrails, and good writing on these topics.

Projects must:

- Be open source with a license file (closed tools may go in *Official docs and guides* only when they are an agent vendor's own docs).
- Have had a commit in the last 6 months, unless the project is a widely used reference.
- Have a README that explains what it does and how to install it.
- Work today. No "coming soon" repos, waitlists, or empty placeholders.

Articles must be specific and practical. Pure marketing posts are not accepted.

There is no star minimum. Small, focused tools are welcome.

## Entry format

```markdown
- [Name](https://link) - One-line description ending with a period.
```

- Describe what it does, neutrally. No "best", "blazing fast", "revolutionary", or emoji.
- Keep it to one line, ideally under 120 characters.
- Link to the repository, not to a fork or a marketing page.
- Keep the section in alphabetical order (case-insensitive).
- If you maintain the project, say so in the PR description.

## How to propose an entry

1. Click the pencil icon on [README.md](README.md) to edit it in the browser. GitHub forks the repo for you.
2. Add your line in the right section, in alphabetical order.
3. Open a pull request and fill in the short checklist.

Not sure which section fits, or want to suggest a new section? Open an issue and ask.

## Removing or updating entries

Open a PR or an issue if a project is archived, unmaintained, renamed, or its description is out of date. A weekly link check also flags broken links.

## Code of conduct

Be kind. Critique tools, not people.
